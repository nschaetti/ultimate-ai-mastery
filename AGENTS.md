# Repository guidance

- Write all repository content in English: teaching prose, exercises, solutions, reference notes, documentation, headings, and human-readable metadata. Keep code comments and Google-style docstrings in English as well.
- Preserve the two purposes: a progressive notebook course and a revisitable reference book.
- Follow `docs/PEDAGOGY.md`. Keep learner and solution notebooks adjacent with matching exercise IDs.
- Cover the libraries themselves, including specialized public subpackages. Do not reduce the scope to APIs useful for a particular AI project.
- Never claim exhaustive symbol coverage from the planning matrix. Follow `coverage/README.md` and retain versioned evidence.
- Prefer primary sources. Link sources beside the claims they support. State deviations from published methods and unknown proprietary details.
- Do not mark a lesson validated without a clean-kernel solution run in its recorded environment.
- Do not replace unfinished lessons with many empty notebooks. Update navigation and coverage when actual content is added.
- Avoid committing datasets, model weights, credentials, learner-specific private notes or heavy notebook outputs.
- Do not impose a license or change the project scope without the owner's instruction.
